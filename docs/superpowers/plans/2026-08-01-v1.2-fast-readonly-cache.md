# TikHub 小红书 MCP v1.2 实施计划

> 执行前提：已确认设计说明 `2026-08-01-v1.2-fast-readonly-cache-design.md`。

## 目标

发布 v1.2.0：保留已修复的 API Key 传递方式，使用可复用的运行环境，提供 5 分钟的成功响应分页缓存与手动刷新，并使只读查询不再逐次请求人工确认。

## 任务 1：先为缓存和刷新补足测试

**文件**

- 修改：`tests/test_xhs_mcp_service.py`
- 修改：`tests/test_xhs_mcp_server.py`

**步骤**

1. 扩展假客户端，记录每个 endpoint 与参数的调用次数。
2. 新增服务层测试：相同 endpoint/参数在 TTL 内只访问假客户端一次。
3. 新增分页复用测试：先请求搜索第 1～3 页，再请求第 1～15 页，断言前 3 页不重复访问且后续页会访问。
4. 新增 `refresh=True` 测试，断言它绕过命中缓存并替换缓存值。
5. 新增异常测试，断言 API 错误和本地错误不会进入缓存，也不泄露 Key。
6. 新增 MCP 工具元数据测试，断言 9 个工具具有只读且非破坏性标注，并接收需要的 `refresh` 参数。

**验证**

```powershell
python -m pytest tests/test_xhs_mcp_service.py tests/test_xhs_mcp_server.py -q
```

## 任务 2：实现服务层的 TTL 分页缓存与刷新

**文件**

- 修改：`plugins/tikhub-xhs-mcp/xhs_mcp_service.py`
- 修改：`plugins/tikhub-xhs-mcp/xiaohongshu_tikhub.py`（仅在客户端安全复用需要时）

**步骤**

1. 在服务实例中增加内存缓存、单调时钟、TTL（默认 300 秒）和并发保护。
2. 将 endpoint、规范化后的参数（含页码/游标/排序/筛选）编码为稳定缓存键；不包含 Key 或认证字段。
3. 扩展 `xhs_call` 的本地入参 `refresh=False`，从转发给 TikHub 的参数中剥离该字段。
4. 命中有效缓存直接返回；`refresh=True` 或缓存过期时请求 TikHub；仅成功结果写入缓存。
5. 让所有 6 个有网络请求的快捷服务方法透传 `refresh`；状态和接口清单保持本地调用。
6. 将客户端创建策略改为服务实例内可复用；若 SDK 的 context manager 无法安全复用，则不改变其关闭语义，并以缓存作为已验证的确定性优化。
7. 保持 401/402/403/404/超时错误映射、白名单校验、脱敏和审计日志行为。

**验证**

```powershell
python -m pytest tests/test_xhs_mcp_service.py -q
```

## 任务 3：为 MCP 工具暴露刷新并标注只读

**文件**

- 修改：`plugins/tikhub-xhs-mcp/xhs_mcp_server.py`

**步骤**

1. 导入并统一使用 `ToolAnnotations`。
2. 为九个工具声明 `readOnlyHint=True`、`destructiveHint=False`；实际访问 TikHub 的工具如实标注外部网络特性。
3. 为搜索、笔记、评论、用户、用户笔记、热榜和通用入口增加 `refresh: bool = False` 并传至服务层。
4. 更新工具描述：默认使用 5 分钟缓存，用户要求“刷新/重新获取”时传 `refresh=true`；调用仍可能收费。

**验证**

```powershell
python -m pytest tests/test_xhs_mcp_server.py -q
```

## 任务 4：加速插件启动并锁定依赖

**文件**

- 修改：`plugins/tikhub-xhs-mcp/.mcp.json`
- 新增：`plugins/tikhub-xhs-mcp/pyproject.toml`
- 新增：`plugins/tikhub-xhs-mcp/uv.lock`
- 必要时修改：`plugins/tikhub-xhs-mcp/requirements.txt`、`scripts/setup-windows.ps1`、`scripts/setup-macos.sh`

**步骤**

1. 将运行时 `uv run --with` 临时依赖改为项目声明、锁定依赖和可复用项目环境。
2. 保留 `env_vars: ["TIKHUB_API_KEY"]`，防止回归 v1.0 的 Key 传递问题。
3. 在干净缓存目录验证首次依赖安装，在已有环境验证第二次 STDIO 启动不重新安装依赖。
4. 不把用户 API Key 写入任何项目配置或锁文件。

**验证**

```powershell
uv run --locked --python 3.12 python -m pytest -q
```

并用 JSON-RPC `initialize` 对 STDIO 进程做握手冒烟测试。

## 完成标准

- 79 个白名单接口没有减少，任意 URL 仍无法调用；
- 同页相同请求在 5 分钟内不产生第二次 TikHub 调用；
- 50 条扩展到 300 条时，已缓存页零新增调用；
- 显式刷新稳定绕过缓存；
- 只读查询可在 `writes` 策略下直接执行，未来写入工具仍需确认；
- Key 不出现在返回、错误、日志、缓存键、Git 变更或 ZIP 文档中；
- GitHub 插件和 ZIP 均能启动，并保留正确的 Key 传递能力。
